# Home.Media

**Home.Media** — это модульная медиаплатформа для Synology NAS и других сред, работающая на базе плагинной архитектуры. Платформа состоит из ядра и независимых плагинов, каждый из которых работает как отдельный Python-процесс.

[![core tests](https://github.com/tro9n4ik/HM/actions/workflows/tests.yml/badge.svg)](https://github.com/tro9n4ik/HM/actions/workflows/tests.yml)

## 📌 Особенности архитектуры

- **Ядро (Core):** Написано на `FastAPI`. Управляет авторизацией, плагинами, маршрутизацией портов, health-проверками, базой данных (SQLite/PostgreSQL) и reverse-proxy к веб-интерфейсам плагинов.
- **Фронтенд (Admin):** Написан на `React` / `Vite` с использованием `Tailwind CSS`. Отвечает за общую панель управления (Setup UI).
- **Плагины:** Самостоятельные пакеты (формат `.hm`, по сути `.zip`), которые запускаются ядром. Каждый плагин имеет свой UI и API.
- **Интеграции:**
  - `telegram_bot` — единая точка входа для взаимодействия через Telegram-бота (бот-хаб).
  - `home_assistant` — интеграция с умным домом с поддержкой Telegram.
  - `torrents` — интеграция с qBittorrent, TMDb и Prowlarr для автоматизации загрузок.

## 🚀 Быстрый старт (Развертывание через Docker)

Проект использует концепцию **Zero-config deploy**. Все секреты (например, `SECRET_KEY`) и настройки генерируются автоматически при первом запуске в `docker-entrypoint.sh`.

### Использование Docker Compose

1. Клонируйте или скачайте архив репозитория:
   ```bash
   git clone https://github.com/tro9n4ik/HM.git
   cd HM
   ```
2. Запустите контейнеры:
   ```bash
   docker-compose up -d
   ```
3. Откройте в браузере: `http://localhost:8142` (или IP вашего NAS) и создайте аккаунт администратора.

### Использование Synology Container Manager
1. Распакуйте исходники в папку на NAS (например, `/volume1/docker/hm3-syn/`).
2. Откройте **Synology Container Manager** → Проекты → Создать → выберите эту папку.
3. Нажмите **Deploy**.
4. После запуска перейдите по адресу `http://NAS_IP:8142`.

## 📦 Управление плагинами

Плагины находятся в папке `plugins/`. При старте контейнера они автоматически перепаковываются в архивы `.hm` и помещаются в `core/dev_data/plugins/`. Установка плагинов возможна через веб-интерфейс ядра.
